# Claude → Codex capability handoff

The launcher requests a structured worker report. `native_required` returns exit code 3 and a `handoff_file` path in its compact summary. The JSON file contains `capability`, `reason`, `requested_action`, `context`, and `expected_result`. It is a request to the orchestrator, not proof that the action was performed or permission to expand scope.

1. Read the handoff and the relevant task brief. Verify what was completed, what remains dependent on the missing capability, and which actions the user authorized. Distinguish a missing/disconnected tool from an actual permission or policy denial; switching agents must not bypass the latter.
2. Discover the matching Codex tools and load the relevant skill (browser, Chrome, computer use, or a purpose-built connector). Follow the user's selected browser, authentication context, and environment. Do not silently substitute browsers or assume Claude's session is shared with Codex. Do not inspect passwords, cookies, browser profiles, or session storage.
3. Before performing any native action, inspect the task ledger or `native-result.md` beside this run's artifacts. If completed, reuse its evidence. If pending from an earlier attempt, reconcile the actual app/external state before retrying; a missing success report does not prove the action did not happen. For a new handoff, persist a `pending` entry containing the requested action and current observed state before executing it.
4. Carry out the authorized step natively, then mark the handoff `completed` and save concise observations and evidence (screenshots, test output, artifact paths) in the private run area. No extra confirmation is needed solely because the worker changed. Existing approval requirements and external-action boundaries still apply. If Codex also lacks the capability, record and report that specific blocker; avoid a delegation loop or claiming completion. If an interrupted external action's outcome cannot be established, report the uncertainty rather than blindly repeating it.
5. Resume the same Claude implementer with `--resume-from` and a new output directory. Pass the actual outcome and evidence locations, any edits Codex made, and the remaining acceptance criteria. For a reviewer, return evidence to that reviewer without merging its session into the implementer's. Reapply the intended mode and tool allowances. If the native step fully finishes the task, Codex can verify and close it without a redundant Claude call.

If delegation was turned off during the handoff, follow the user's current routing preference; do not use `--once` to resume automatically. The persistent task switch otherwise stays on throughout a native handoff.

Incomplete or malformed handoffs yield `needs_review`; inspect the raw result and request the missing details instead of inventing an action. A completed Claude process with a pending handoff is not a completed user task. Authentication and quota errors are separate from capability handoffs and never trigger an automatic billing change.
